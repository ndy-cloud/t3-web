T3 出行香港业务消息触达与安全认证解决方案

一、业务现状：香港业务需要重新规划“登录 + 行程消息 + 关键通知”

网约车业务同时具备高频、实时、双边用户和安全敏感四个特征。乘客下单后会持续等待司机接单、车辆到达、行程开始与支付完成；司机端则需要接收派单、改派、奖励、申诉与安全通知。任何一个关键节点发生延迟，都可能直接影响叫车体验与履约效率。

T3 进入香港后，还需要处理本地手机号登录体验、海外消息基础设施与数据中心选择。建议将三项产品分工设计：极光认证负责注册登录入口，AppPush 负责 App 内高频通知，SMS 负责强提醒、服务通知和未安装或未在线用户的手机号触达。

香港业务触达链路 从账户进入，到实时履约，再到安全与运营消息
T3 香港业务的四类关键信号
账户入口 注册、登录、退出后重新登录

在 Android 与 iOS 端使用香港号码一键登录，减少手机号和验证码输入步骤。

订单履约 派单、接单、到达、上车、完成

以 AppPush 作为主通道，按乘客、司机、行程状态与优先级设置发送策略。

关键异常 取消、改派、支付、安全事件

AppPush 快速提醒，必要时使用 SMS 向手机号补充触达。

用户运营 优惠券、会员、召回、司机激励

结合标签、别名和用户状态分群，避免无差别群发影响体验。

二、三项产品的角色定位与选择理由

三项产品不互相替代。它们分别解决“进入 App”“App 内实时消息”“手机号关键触达”三个问题，共同覆盖一段完整出行服务链路。

产品 A EngageLab AppPush

用于乘客端和司机端的高频 App 消息。支持 Android、iOS、HarmonyOS，并覆盖 FCM、APNs 与主流 Android 厂商通道。

  • 支持通知栏消息与自定义消息
  • 支持按厂商通道配置发送策略
  • 提供送达、展示、点击与折损分析
  • 提供 Push、Report、Schedule、Device API
最适合订单状态、司机派单、车辆到达、行程完成、运营召回
产品 B EngageLab SMS

用于关键服务消息和手机号触达。提供全球运营商直达网络、控制台与 API 两种发送方式，并支持模板和签名审核。

  • 覆盖 190+ 国家与地区
  • 支持交易通知与营销短信
  • 按实际发送量计费，无月度最低消费
  • 支持发送记录、费用与效果数据查询
最适合行程变更、支付提醒、安全通知、未在线用户提醒
产品 C 极光认证 JVerification

用于香港手机号快捷注册登录。当前香港业务仅提供一键登录能力，支持 Android 与 iOS。

  • 用户无需手动输入手机号即可注册登录
  • 无需输入短信验证码，缩短登录操作路径
  • 香港一键登录支持 Android 与 iOS
  • 可同时服务乘客端与司机端登录入口
最适合乘客注册登录、司机注册登录、退出后重新登录
HONG KONG ACCESS

香港号码一键登录建议

将一键登录放在乘客端与司机端的用户旅程入口，减少手机号和短信验证码输入步骤，提高注册登录效率。

乘客端新用户注册、日常登录与重新登录
司机端司机注册、登录与重新进入工作台
支持平台香港业务支持 Android 与 iOS

五、数据中心节点选择与合规架构

EngageLab AppPush 支持新加坡、巴西、欧洲、美国、香港、日本等数据中心选择。T3 主要业务区域为香港，建议在技术与合规评审阶段优先评估香港节点，再根据后续业务区域规划其他节点。

香港 T3 香港业务建议优先评估

支持 AppPush 相关数据在香港区域部署，减少不必要的跨境传输路径，便于统一管理本地访问权限与日志。

新加坡 面向东南亚业务扩展

适合承接东南亚区域业务，帮助按区域隔离数据与服务，简化多市场的数据流向管理。

日本 面向日本市场

支持日本业务区域化部署，缩短跨区域处理链路，便于针对当地数据驻留要求开展评估。

美国 面向北美市场

支持北美业务独立部署与权限隔离，便于按业务区域管理数据访问、运维人员和审计记录。

欧洲 面向欧洲市场

帮助欧洲用户的 AppPush 相关数据在欧洲区域部署，便于开展数据驻留与跨境传输治理。

巴西 面向巴西及拉美市场

支持巴西及拉美业务区域化部署，减少跨区域数据链路，便于落实当地的数据访问与留存策略。

节点选择对合规治理的核心帮助
数据驻留 区域隔离 跨境链路控制 权限与日志审计

根据用户所在区域选择数据中心，可以缩短数据跨区域流转链路，并为数据驻留、访问控制、日志审计及跨境传输评估提供更清晰的技术边界。
